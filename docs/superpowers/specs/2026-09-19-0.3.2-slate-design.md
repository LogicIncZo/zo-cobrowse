# 0.3.2 slate design — Zo-composed recipes (compose mode)

**Date**: 2026-09-19
**Status**: Owner-chartered ("Make this as goal for 0.3.2 and proceed with tickets" directive, same day). Milestone `0.3.2` (id 9).
**Baseline**: Recipes R1 + recorder (2026-09-14), #228 generate fills, R2 workspace write-back + R3 library surface (v0.3.1.0, PRs #275/#276), stabilization round 1 (v0.3.1.1, PR #279). Handoff loop (0.2.7), no-auto-submit rule (#26/v0.2.0), capture redaction (#243).

## Goal

**Zo attempts to compose a recipe for a stated goal, involving the human only when required** — values, ambiguity, and verification. Nothing else.

## First-principles frame (why the slate is shaped this way)

A recipe is a *claim* that an action sequence achieves a goal on a site; deterministic playback makes it repeatable, not correct. A human-recorded recipe is correct because a human click carries intent **and** verification simultaneously. A Zo-composed recipe is a **hypothesis**: Zo can supply structure (paths, steps, param naming, checkpoint placement), but the correctness signal must come from the human. Hence the slate's two moves:

1. **C1** captures what Zo already demonstrated (save a handoff run's action log as a draft) — the human already watched it work, so the verification cost is one rehearsal run.
2. **C2** makes Zo the *driver* of composition with hard-coded parks: values are human-only (Zo never fills — boundary-enforced, not prompt-enforced), ambiguity parks, submits are checkpoints (the no-auto-submit rule is absolute), and the first replay is a mandatory rehearsal that promotes the draft to verified.

The recorder is event-sourced (capture-phase listeners, no trust filtering) and the action executor can stream an equivalent sink — so "record what Zo does" is a producer added to an existing assembler, not a new subsystem. The E-INVARIANT is actor-agnostic: a machine check on the artifact, whoever produced it.

## Cross-cutting rules

1. **E-INVARIANT at compose time**: `validateRecipe()` gates every composed draft — a composed artifact can never embed an unguarded submitish click. Machine-checked, tested.
2. **Human values only**: Zo never invents fill values; Zo-sourced fills are refused by the boundary in compose mode, and any Zo-sourced fill value from a C1 run is discarded (param without default). Every persisted default traces to human input.
3. **No-auto-submit absolute**: compose clicking never targets submitish controls; submits become `human` checkpoints. Prompt rule is belt, boundary check is braces.
4. **Verification before trust**: composed drafts ship `draft:true, composedBy:'zo', verified:false`; the first replay is a rehearsal with unskippable checkpoints (no "Skip check", no force); success promotes to verified with a patch bump.
5. **Redaction unchanged**: the #243 guarantees hold — sensitive fields never emit values, sensitive pages collapse; the executor sink strips values at source.
6. **Player determinism untouched**: compose changes how artifacts are *born*, never how they play.
7. **Docs move with the release** (standing rule): updates page entry, guide sections, BACKLOG rows, QA_REPORT round log, manual-checklist additions land with the release train.

## Verification criteria (summary — full lists in the issue bodies)

- C1: unit (assembler pruning, param provenance, drift-stable provenance) + integration on the fake bus (handoff run → save → validate → rehearsal promotes; no Zo-invented value persists) + e2e + schema + prompt-eval refresh for the cleanup variant.
- C2: unit (pruning, compose instructions marker, park classification) + integration (parks, boundary refuses fills, SW-restart resume, rehearsal) + e2e (`27-recipe-compose.spec.ts`) + bang/message schemas + prompt-eval refresh.
- Both: `bun run verify` 4/4 per PR; **executor-log assertions prove zero fills and zero submitish clicks executed in compose**; manual-checklist rows for shell-only surfaces.
- Full gates per PR; QA round before release-prep.

## Out of scope

Fully-autonomous compose on trusted sites (future: the #47 autonomy dial applied here); blind scaffold authoring without a browser; visual step editor; scheduling/auto-sync; Zo-side execution (documentation-not-execution boundary from R3 stands); credential storage (never).
