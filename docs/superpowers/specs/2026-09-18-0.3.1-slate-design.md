## Build order

**R2 → R3.** R3's SKILL.md export prefers R2's deterministic `write_file` transport, and the library popup's "↥ Save to workspace" row action renders only when R2 shipped. R2 is also the smaller diff (one message + handler + two UI offers vs a new panel surface).

## Versioning & release model

- **`v0.3.1.0`** — features, so this is an owner-approved PATCH-segment exception on the 0.2.9 precedent (recorded in CONTRIBUTING.md); MINOR stays the default for feature slates.
- Slate model: **one release after both lanes merge** (not the 0.2.8 per-fix model).

## Cross-cutting rules (inherited)

1. **Round-trip invariant (R2)**: `save → load → validateRecipe → playback` byte-equivalent; the written shape is exactly what the loader parses today. No new format, no migration.
2. **E-INVARIANT at write time**: `validateRecipe()` re-runs before any `write_file` — a written recipe can never contain a state the player would refuse.
3. **Export is documentation (R3)**: Zo reading a SKILL.md can describe and suggest recipes; execution stays extension-side in the deterministic player. Zo-side execution stays out of scope.
4. **Redaction**: no captured values, no param defaults (R3 export runs `redactValue` over defaults; `contextFile` rides as a path reference only). The recorder's never-capture rule (shipped in the #243 round) is untouched.
5. **Path confinement**: every workspace target goes through `safeWorkspacePath`; traversal refused before any MCP call.
6. **Determinism**: recipe persistence never rides an LLM turn — MCP `write_file` only (the chat-route write is a fallback with an honest "best effort" note, never the primary path).
7. Stabilization protocol: any QA round over these lanes files findings per the standing playbook; fixes ride `0.3.1.N` point releases.

## Verification criteria

- R2: unit (serialization, slug/path confinement refusals, drift→`bumpVersion`) + integration on the fake bus (save → `read_file` round-trip; overwrite-confirm; heal → save-healed → re-import without re-heal) + e2e extension of `23-recipes.spec.ts` (record → learn → save → run-from-workspace replays the written artifact; mock server gains an in-memory `write_file` route).
- R3: unit (export builder — frontmatter + redaction; rename/delete semantics) + integration (`RECIPE_RENAME`/`RECIPE_DELETE`/`RECIPE_IMPORT` message contract via `tests/schemas/messages.ts` and background coverage) + e2e for the library popup happy path + the user guide (`docs/guide/recipes.md`) passing the docs build.
- Full gates per PR (`bun run verify`), prompt evals untouched (no prompt changes planned — any prompt-adjacent change re-runs `evals:live`).

## Out of scope (unchanged from the issue non-goals)

Auto-sync/scheduling between local and workspace copies; recipe editing UI beyond R3's rename; Zo-side recipe execution; branching/looping DSL; credential storage (never).
