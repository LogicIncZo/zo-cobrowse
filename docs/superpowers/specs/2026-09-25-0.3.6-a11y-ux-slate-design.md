## A11Y1 — Accessibility review round 1 (flagship audit)

Method mirrors the security rounds: mechanical sweeps first, deep-dives per surface,
findings ledger in a new `docs/qa/accessibility-review.md` (round-1 record, same
living-doc cadence as the threat model). Audit lanes:

1. **Keyboard & focus** — tab order and focus visibility on all four surfaces; Esc
   behavior consistency (pickers, popovers, popups, streaming cancel); focus trapping
   and restoration (skills `/`, files `%`, `@` popups; recipe library popup; write-assist
   popover; settings tabs); Enter/Space activation on custom controls — every
   `div`-as-button audited (`sidepanel.js` chat tabs, chips, footers, history cards,
   action cards; `options.js` settings nav, Show/Hide toggles).
2. **Semantics & ARIA** — tab bars need real tab semantics or explicit ARIA (chat tab
   strip `#chat-tabs`, settings `#settings-nav`); toggle state exposure (📷 image toggle,
   enable toggles, Show/Hide); icon-only controls carry accessible names (✕ tab close,
   ⬇ Latest, ↥/⤓/✎/🗑 library rows, footer chips); streaming log as a live region
   (`aria-live`/`role=log`) so assistant output is announced; `lang` attributes.
3. **Visual** — contrast pass over both themes (muted prose, footer chips, badge-new,
   reasoning text, disabled states) against WCAG AA (4.5:1 text, 3:1 large/UI);
   focus outlines survive the theme CSS; `prefers-reduced-motion` respected (pulsing
   background-chat dot, smooth scrolls, animations); hit-target sizes on dense rows
   (library popup rows, chat tabs).
4. **Platform & strings** — extension pages render with Chrome's accessibility tree
   intact (no `aria-hidden` misuse, no positive `tabindex`); a11y-relevant strings
   (aria-labels) join the #315 i18n census so they can't regress unaccounted.

**Fix disposition (standing rule):** quick fixes in-round (TDD where behavior is
testable; the e2e harness can assert roles/labels/tab-stops on the panel-as-tab and
options pages); larger restructurings → `0.3.6.N` stabilization points. Findings
ledger rows in `accessibility-review.md`; queue drains before release (`qa-gate`).

**Deep-dive surfaces:** side panel (chat log, composer, tab strip, history, mode bar),
options page (tabs, prompts editor, Jev card), write-assist popover (shadow DOM —
focus/scale/Esc inside the shadow root), recipe library popup + checkpoint/review cards.

## UX1 — The waived #244 walkthrough, run

- **Instrument:** `docs/qa/manual-panel-checklist.md` (the #254 scaffold incl. 0.3.0
  additions), extended with a "0.3.4/0.3.5 additions" section (Jev card, one-save
  settings bar, connection pane two-field reality, threat-model-era surfaces).
- **Execution:** OS-level browser automation (computer-use) against a real Chrome
  profile with the current build loaded — the real panel shell, not the e2e
  panel-as-tab. Two passes: **fresh profile** (onboarding: install → token → first
  ask → starter chips) and **existing profile** (daily flows: pickers, modes, tabs,
  history, gated flows, error paths). The owner gets the log for spot-check; their
  walkthrough duty under #244 is discharged by this log unless they re-charter.
- **Log:** `docs/qa/usability-walkthrough-0.3.6.md` (the scaffold's named 0.3.0
  location is superseded — the surface walked is eight releases newer). Every friction
  point files with a concrete UX proposal (the #244 acceptance bar — "feels slow"
  doesn't count). Quick wins fixed in-slate; larger redesigns triaged to BACKLOG with
  rationale.
- **Close-out:** fresh ticket (referencing the #244 waiver) closed with the log;
  checklist updated where flows changed.

## Release model

Standing train: spec PR → zo-loop cycles per ticket → release-prep (3 gates) → bump PR
→ tag `v0.3.6.0` → docs catch-up → dev→main promotion. Version 0.3.6.0 (review lane,
follows the 0.3.5 precedent).

## Success criteria

- `docs/qa/accessibility-review.md` round-1 record: all four lanes walked with
  file:line evidence; ledger triaged; quick fixes merged.
- Walkthrough log committed for both profiles; every finding carries a proposal;
  checklist updated; #244 waiver loop closed with evidence.
- `bun run verify` + e2e + evals + qa-gate green; `v0.3.6.0` tagged, promoted, docs
  caught up.
