## SEC1 — Round-2 security review (flagship audit)

Same method as #243, on current `dev`:

1. **Sink inventory re-run + diff** — `bun scripts/security/sink-inventory.ts` vs the
   134-site baseline in `security-review.md`. Every added site (Jev transport, recipe
   save/heal/export/import, compose obs, settings derivation, 0.3.3 UI work) accounted
   for in the doc; message-roster diff checked against `tests/schemas/messages.ts`.
2. **Deep-dive: Jev egress** — `redactStateForJev` (`lib/jev.js`) composed with the
   formfill heuristics at the call site: redaction completeness (nested choice criteria,
   `contenteditable` text, value-ish keys the structural strip misses); key only ever an
   `Authorization` header (never URL/body/log — `lib/debug-log.js` discipline); the
   user-overridable `jevApiUrl` treated as user-config SSRF surface (same accepted
   posture as `zoApiUrl`), with scheme sanity checked; `JEV_TEST` path included.
3. **Deep-dive: workspace write-back** — `safeWorkspacePath` confinement audited at
   every call site (`RECIPE_SAVE`, `RECIPE_SAVE_HEALED`, `RECIPE_IMPORT`, skill export);
   overwrite probe-then-confirm discipline; the no-model-authored-value-persists
   backstops (`withoutParamDefaults`, `literalFillValueCount`) still hold on the compose
   paths; exported SKILL.md carries no defaults/literals/contextFile contents.
4. **Deep-dive: recorder/compose privacy** — sensitive non-emission for fields without a
   `type` attribute (`contenteditable`); sensitive-span collapse in BOTH compose
   producers (Zo sink records + boundary parks + human `RECIPE_OBS`); human fill values
   become param defaults only where intended; `storage.session` run payloads (`cobrowse_recipe_runs`, `cobrowse_handoff_runs`, parks) carry no secrets.
5. **Adversarial e2e extension** — the `e2e/25-security-negative.spec.ts` +
   `hostile.html` pattern extended for any new page-observable surface the roster diff
   shows (content-script listener set diff first).
6. **Findings ledger** — appended to `security-review.md` (round 2 section). Quick fixes
   in-round (the #243 precedent); P1–P3 → fix cycles in this lane; accepted items
   documented with rationale. The findings queue (`docs/qa/findings/`) must be empty at
   release (standing `qa-gate` rule).

Out-of-audit re-checks (cheap, same pass): `backend/relay.ts` still dormant and
unreferenced; `manifest.json` permission surface unchanged; storage sensitive-key
routing for the two new Jev keys.

## SEC2 — Threat-model doc (the lane's durable artifact)

New `docs/qa/threat-model.md`, graduating `security-review.md` §8:

- **The vector class**: page content reaches the model by design; a hostile page can
  always *attempt* injection. Security question = what a successful injection can DO.
- **Containment inventory** (code, not prompt-hoping): no page→extension channel
  (proven on the wire, e2e/25), `normalizeActions` verb allowlist, sensitive-form park,
  submit backstops, filledPages no-click, handoff/compose boundaries, user visibility
  of every action, no silent exfil channel, pull-loop budget — mapped **per surface**:
  capture, actions/executor, recipes + compose, Jev fast path, write-assist, settings.
- **Residual accepted risks**: done() social engineering, thread poisoning, Zo-side
  server tools, Jev as second processor (opt-in, redacted state).
- **Living-doc rule**: updated every release alongside QA_REPORT (same docs-catch-up
  train); new surfaces land here first when they ship.
- Cross-links: `security-review.md` §8 points here (§8 stays as the round-1 record);
  AGENTS.md links it; `PRIVACY.md` keeps its user-facing voice and links here for the
  deep story.

## Findings → releases policy

- In-round nits: fixed inside SEC1's PRs (the #243 pattern).
- Anything larger: its own fix cycle in this lane, shipped as a `0.3.5.N` stabilization
  point (one fix = one release, the 0.2.8 rule).
- No prompt changes are expected; if a fix must touch prompts, the `evals:live` cache
  refresh rides that fix's PR.

## Release model

Standing train: zo-loop factory cycle per ticket (implement → verify → adversarial
review → merge) → release-prep (3 gates: `verify`, `evals`, `qa:gate`) → bump PR → tag
`v0.3.5.0` (release.yml publishes the zip) → docs catch-up (CHANGELOG, updates.md,
BACKLOG, AGENTS.md, QA_REPORT, threat-model; VitePress build before commit) → dev→main
promotion PR (merge commit, drift gate green after the #265 re-pin).

## Success criteria

- Sink-inventory diff reconciled against the 134-site baseline; doc updated.
- Findings ledger fully triaged; `docs/qa/findings/` empty at release.
- `threat-model.md` live, cross-linked, carrying the living-doc rule.
- `bun run verify` + e2e + evals green; drift gate green.
- `v0.3.5.0` tagged, promoted to `main`, docs caught up.
