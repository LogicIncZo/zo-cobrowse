# 0.2.7 Release Slate — Polish & Daily-Use Round (design)

**Date:** 2026-08-30 · **Status:** approved in-session · **Milestone:** 0.2.7 (file issues at implementation start)

## Goal

A second consecutive hardening round, this time paired with user-visible daily-use wins. 0.2.6 closed observation-driven bugs and built the measurement layer (coverage, perf baseline, prompt-token audit, i18n scaffolding); 0.2.7 *spends* that layer: it executes the follow-ups the 0.2.6 audits explicitly named, and adds three small features that remove daily friction (chat export, stale-build guard, streaming-reasoning probe).

Deliberately **not** a feature-slate round otherwise: the Tier-1 carry-over (#19 model picker, #10 cross-tab actions, #29 watch & scheduled tasks) stays parked for 0.3.0 planning, as does the i18n string migration (#68 round 2). Prerequisite: **v0.2.6 tags first** (owner testing pending); 0.2.7 work lands on `dev` on top of the merged 0.2.6 slate.

**Lane E — Zo handoff — is the round's flagship** (added in review 2026-08-30): delegate-mode runs where the user primes intent + context and Zo takes over in the background up to a hard boundary. 0.2.7 ships the primitives plus one read-only reference scenario; everything form-touching waits for 0.3.0 (see Out of scope).

### Lane E — Zo handoff (delegate-mode runs; the round's flagship)

The pattern being built: **Prime** (intent + context: tab refs, `%` files, `/` skills — all existing) → **Run** (unattended navigate/extract loop) → **Boundary** (park, never cross) → **Report** (progress + final artifact) → **Interrupt** (watch/abort anytime). A handoff is bounded-duration work in this session — distinct from #29 watch/scheduled (long-running), but the run object + continuation loop built here is #29's future engine, and the boundary checker is #47 autonomy dial's seed.

Pinned decisions:

- **Single-tab sequential runs** — the handoff drives ONE tab; Zo navigates page-to-page. No #10 dependency; multi-tab handoff upgrades when #10's actions half lands (0.3.0).
- **Event-driven, MV3-safe run loop** — never a SW-resident timer: each stream returns actions → background executes → sends an auto-continuation turn (progress report + "keep going") → repeat until Zo `done()` or budget. Run state persists via the `sw-cache.js` `storage.session` pattern; a SW restart mid-run **resumes**, never strands. `finishStreamWithTabLoop` already proves the execute-then-continue shape.
- **Trigger**: `!handoff <goal>` bang command (`kind:'handoff'` in the discriminated union) — explicit, composes with pickers/tab refs like any send. No silent policy: unattended execution only ever starts from this command.
- **Fixed default boundary** — no submit/purchase/send/delete/payment, generalized from the #26 no-submit rule; the boundary checker (`isActionAllowed`) lives in `lib/handoff.js` and reuses `isSensitiveForm` signals. Anything beyond the boundary parks into the **existing `pendingActions` review card** (#26 UX) — the user performs terminal actions. (Per-site grants = #47, later.)
- **Budget** — max turns / navigations / minutes (defaults in `config.js` `DEFAULTS`, schema'd); hard stop + park on exhaustion.
- **Surfacing** — the run lives in its own chat tab (pulsing dot exists); one compact progress line ("12/20 · extracting · ⏸ boundary pause: checkout"); abort button; run-tab marker (badge/title "🤖 working…"); closing the run tab aborts.
- **Notification** — one-shot `chrome.notifications` "handoff done / blocked" (new `notifications` permission — the point of delegating is walking away).

**Reference scenario (0.2.7's acceptance bar): read-only digest.** "Read these 5 tabs / search results, extract, compose a comparison digest" — navigate → extract → repeat → compose, zero form interaction, zero boundary ambiguity. It exercises every primitive (state machine, continuation, budget, progress, abort, report). Form-touching handoffs (data-entry with parked submits) are 0.3.0's second scenario, once the bones are proven.

## Build order

Lane C items (3, 4, 5) first — small, independent, warm-up. Then **Lane E (9→12, in dependency order: pure half, loop, UX, marker/notification)** — the flagship gets the largest contiguous block. Then Lane D (6, 7, 8; 7's idempotency prerequisite first). Lane A (1) when evals refresh budget is available (needs `ZO_API_KEY`). Lane B interleaves: **2-0 first** (the instrument), then 2a (needs the owner's diagnostics export), 2b (can proceed on its micro-bench), 2c (only on evidence).

## Cross-cutting rules (inherited from 0.2.6)

1. **Prompt changes** stale the evals cache → `bun run evals:live` refresh rides the same PR; case ids stable (stream-replay fixtures route on them).
2. **Tests first where pure logic**: `lib/` halves get schemas + unit tests before wiring.
3. **Evidence rule**: perf work quotes before/after numbers (baseline instrument or committed micro-bench); prompt work quotes before/after token totals. No intuition-driven changes.
4. **Unattended-execution safety rule (Lane E)**: handoff ships read-only-first; the boundary checker and budget cap are acceptance-gated (tests prove the loop parks, not crosses); unattended execution only ever starts from an explicit `!handoff` command. Any future scenario that touches forms re-opens this rule explicitly.
5. Git-flow: one `fix/*`/`feat/*`/`chore/*` branch per item, PR to `dev`; `main` promotion + tag `v0.2.7` is the deliberate release step. Issues filed per item (#91+) at implementation start.

## Out of scope (0.2.7)

- Tier-1 carry-over: #19 model picker, #10 cross-tab actions, #29 watch & scheduled tasks → 0.3.0 planning. (Lane E's run loop + boundary checker are #29's engine; multi-tab handoff waits for #10's actions half.)
- **Form-touching handoff scenarios** (data-entry batches with parked submits, booking prep) → 0.3.0's second handoff scenario, after the read-only bones are proven in real use. Per-site boundary grants (#47 autonomy dial) likewise.
- Remote telemetry: **out by design** — no receiving endpoint, page-DOM/token privacy surface; the diagnostics-export → GitHub-issue flow is the consent-carrying transport. Revisit only at the Web Store milestone (#11).
- i18n string migration + second locale (#68 round 2).
- All current 0.3.0 milestone items (#46–#54), Web Store (#11), shared sessions (#15).
- `sidepanel.js` module split (revisit as its own low-risk round).

## Release mechanics

`v0.2.6` tags first (owner testing pending) — 0.2.7 accumulates on `dev` above it. Changelog `[Unreleased]` accumulates the lane merges (the 0.2.6 slate moves under its `0.2.6` heading at tag time). BACKLOG.md's milestone section tracks status. Manifest bumps to `0.2.7` at release prep; dev→main PR gated by CI + `drift` job; manual panel checklist before promotion.
