# 0.3.0 Slate Design — harden & slim (prompt-optimization train + review rounds)

**Decided:** 2026-09-15 (owner). The prompt-optimization lane moved out of 0.9.0 into its own train; the security-review and usability-review rounds were chartered alongside (owner direction, PR [#245](https://github.com/LogicIncZo/zo-cobrowse/pull/245)).
**Milestone:** [`0.3.0`](https://github.com/LogicIncZo/zo-cobrowse/milestone/7) · **Release model:** ONE `v0.3.0.0` after all items merge (slate model, not the per-fix bash model). Owner-called release. Review-round fixes that miss the slate ship as `0.3.0.N` stabilization points (`.STAB` = fixes only, never features).

## Charter

0.3.0 is a **harden-and-slim release** between the 0.2.9 quick-wins train and the big 0.9.0 feature slate: slim the prompts that ride every turn (the prompt-optimization lane, #235–#239, moved out of 0.9.0 by owner charter), then audit the **finished** surface with two dedicated review rounds — security ([#243](https://github.com/LogicIncZo/zo-cobrowse/issues/243)) and usability ([#244](https://github.com/LogicIncZo/zo-cobrowse/issues/244)). The milestone name was freed when the old 0.3.0 renamed to 0.9.0 on 2026-09-02.

**Versioning pin:** 0.3.0 is a proper MINOR feature slate — the 0.2.9 PATCH exception does **not** carry over (policy in CONTRIBUTING.md).

## Lanes

### Lane P — prompt optimization (lands FIRST)

The flagship lane. Build order inside the lane: **#236 → #235 → #237 (spike-gated) → #238**; the #239 spike runs anytime inside the lane (timeboxed, no product code). #236 goes first because #235 slims the canon #236 produces; #238 locks the post-trim numbers.

### Lane S — security review (#243) · Lane U — usability review (#244)

**Sequencing (owner-pinned): both rounds run AFTER Lane P lands**, on the frozen 0.3.0 surface — #243's verdicts must cover #235's new MCP `write_file` install path, and #244 walks any UI the lane touched. The slate cannot close until both rounds close with findings triaged. The rounds run parallel to each other.

## Cross-cutting rules (inherited)

1. **Lane A evals discipline** — every prompt-text change runs `bun run evals:live` in the same PR (the cache is keyed on the prompt hash: an edited prompt goes stale → offline `bun run evals` red until refreshed); eval case ids stay stable.
2. **Tests first where pure logic** — `lib/` halves get Zod schemas + unit tests before wiring (`tests/schemas/*` is the contract layer; extend the schema first, then the code, then the test that validates output against it).
3. **Evidence rule** — prompt work quotes before/after token totals from `docs/qa/prompt-bloat-audit.md` (regenerate via `bun scripts/prompt-audit/prompt-audit.ts`); no intuition-driven rewording.
4. **#235 invariant — never lighter than the verified install:** the inline tail only slims to a skill pointer once the installed skill's presence + version are verified (canary read-back); the inspector shows tail + install state.
5. **Drift discipline** — a newly load-bearing MCP tool or API endpoint joins `REQUIRED_MCP_TOOLS`/`REQUIRED_OPENAPI_PATHS` (`scripts/zo-drift/lib.ts`) with the baseline re-pinned in the same PR (`bun run check:drift --update-baseline`).
6. **Git-flow** — one `feat/*`/`fix/*`/`chore/*` branch per issue, PR to `dev`; the dev→main promotion + tag `v0.3.0.0` is the deliberate release step (**merge commit, never squash**).
7. **Findings gate** — actionable review-round findings file into `docs/qa/findings/` in the playbook format (`scripts/qa/validate-findings.ts` clean); the CI `qa-gate` job blocks the promotion until the queue is drained (fix / file on GitHub / dismiss with written rationale).

## Release mechanics

1. Lane P merges issue-by-issue (`feat/*` → `dev`; CI + evals + e2e green per PR). #237 may close NO-GO with probe evidence — that is a valid slate outcome, recorded in-issue.
2. On the frozen surface, #243 and #244 run their rounds; quick-win fix PRs may follow; the findings queue drains (fix / file on GitHub / dismiss with rationale).
3. `chore(release)` version bump (manifest + package, CHANGELOG stamp) → dev → dev→main promotion PR (**merge commit**) with `qa-gate` + `drift` jobs green → tag `v0.3.0.0` → `release.yml` publishes → manual-panel checklist pass logged in the promotion PR.
