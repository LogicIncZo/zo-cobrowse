# v0.2.0 Competitive Analysis — Zo Co-browse vs the agentic-browser field

**Date**: 2026-08-20
**Status**: Approved (scope decision made in-session; feeds the four 0.2.0 design specs)
**Decides**: the v0.2.0 feature set — #26 form-fill, #29 Watch & Scheduled Tasks, #10 cross-tab actions, #19 model picker
**Research**: three parallel web-research passes (agentic browsers, companion extensions + co-browsing, agentic checkout + monitoring categories), sources listed at the bottom.

## 1. Market context (August 2026)

- **OpenAI sunset the standalone Atlas browser on 2026-08-09** (~10 months after launch) and folded agentic browsing into the ChatGPT desktop app **plus a ChatGPT Chrome extension**. The extension form factor is now the validated strategy, not a compromise — and it puts a first-party competitor in our exact niche.
- The market consolidated around **Perplexity Comet, Dia, Opera (Operator/Neon), Fellou**; Skywork pivoted out of browsers to a workspace agent.
- Pricing converged on **free tier + ~$20/mo paid** (Comet Pro, Dia, Opera Neon, Fellou Plus).
- **Autonomous payments got retrenched everywhere.** OpenAI walked ChatGPT Checkout back to confirmed checkout; Google's agentic checkout "always asks permission first"; 1Password/Bitwarden/Proton Pass all ship *mediated* fill (agent never sees plaintext, human approves). The industry converged on the position this repo already holds (owner decision 2026-08-15: no saved profiles/identities, secrets stay with the user's password manager).

## 3. Category deep-dives

### 3.1 Form-fill & confirm UX (feeds #26)

- Every major player pauses at sensitive steps; Copilot Vision has the most detailed model: first-use consent, supervision by action category (purchase/send/delete) *and* site category (banking/email), approval before off-task navigation, and a **payment takeover** — the agent refuses to type secrets and hands the tab to the user. Atlas explicitly never accessed autofill data or saved passwords.
- The Smashing Magazine agentic-UX pattern library (Feb 2026) codifies it: **Intent Preview** (plain-language plan + Proceed / Edit / Handle-it-myself), **Autonomy Dial**, **Action Audit & Undo**, escalation pathway. Recommended rollout order: preview + undo first, act-with-confirmation second, autonomy last.
- **Nobody ships a pre-fill review UI.** Magical, Simplify, FillApp, Chrome-native autofill are all one-click fill. A field-by-field editable review table (masked secret-looking values, one Confirm) would combine Magical's speed with Copilot-grade safety — a genuine differentiator, and it is exactly what #26 already designed.
- Chrome has **no `chrome.autofill` API** — extensions cannot read the browser's saved cards/addresses. Don't try; keep secrets with the user's password manager (mediated-fill direction of 1Password "Secure Agentic Autofill" / Bitwarden Agent Access SDK is a future integration point, not 0.2.0).

### 3.2 Scheduled tasks & monitoring (feeds #29)

- Comet's **Tasks** (scheduled or conditional: price/flight watches, morning briefings; email/push alerts) is called out as its strongest retention mechanic, gated to Max for full autonomy. Fellou ships scheduled tasks + monitoring with tier quotas. ChatGPT Tasks/Work added cron-style connected-app tasks.
- Dedicated monitoring is a mature category (Distill, Visualping, changedetection.io, Sken.io). 2026 table stakes there: selector pinning, condition filters, and **AI-semantic change detection** (NL watch conditions + plain-language change summaries). Frequency tiers split local (seconds, free) vs cloud (metered, paid) — cloud exists because **browser-closed checks need a server**.
- MV3 engineering facts: `chrome.alarms` is the only durable scheduler (min 30s, arbitrarily batched — never promise precise timing); the service worker dies ~30s idle (state must live in storage); FCM push is the only external wake mechanism; `chrome.notifications` + badge are the local notification channels; email/Slack need a backend (Zo-side, later).
- **Open ground:** no monitoring product has a full DOM-seeing agent behind the watch. The **monitor→act→confirm bridge** (change detected → Zo opens the page, runs a follow-up, fills the form, parks at the #26 confirm gate) is the wedge — Distill can diff, Comet can schedule, but neither closes the loop inside the user's own browser with a confirm gate.

### 3.3 Cross-tab actions (feeds #10)

Table stakes at Atlas/Comet/Dia/Fellou. Our 0.1.0 shipped the *context* half (T1…Tn references + `read_tab`); the *actions* half (routing an action to a referenced tab, tab management verbs) is the remaining parity gap — and the #29 bridge reuses it.

## 4. Verdict — the 0.2.0 scope

Chosen (option "Everything", in-session 2026-08-20):

| Feature | Competitive justification |
|---|---|
| **#26 Form-fill batch + confirm-before-fill** | Closes the biggest table-stakes gap; the review-table confirm is a differentiator nobody ships; positions us on the industry-converged safety norm. |
| **#29 Watch & Scheduled Tasks** (unifies tickets #14 + BACKLOG #16/#17) | Biggest capability gap vs Comet/Fellou; AI-semantic verdicts match the 2026 monitoring table stakes; the monitor→act→confirm bridge is our wedge. |
| **#10 Cross-tab actions** | Completes multi-tab agentic parity; required by #29's bridge routing. |
| **#19 Model picker** | Quick win every BYO-model competitor has; reuses the existing catalog cache + `model_name` plumbing. |

**Build order: #19 → #26 → #10 → #29** (smallest first; #29's bridge consumes the other three).

## 5. Explicitly deferred (with rationale)

| Deferred | Rationale |
|---|---|
| Memory across sessions | Valuable but needs a Zo-side memory primitive to be more than a hidden config blob; revisit with Zo API roadmap. |
| Voice interface | Comet-only advantage among leaders; high build cost, low wedge value. |
| Post-hoc undo / action rollback | Strong pattern (Opera) but requires DOM state snapshots; revisit after #26's confirm gate ships (prevention before cure). |
| Payment rails (AP2 / x402 / ACP / TAP) | All watch-only for us: AP2's Open→Closed mandate transition is literally a confirmation surface we could render later (v0.3+ idea); x402 real volume (~$28K/day) doesn't justify engineering. |
| Shared sessions #15/#18 | Real category (Surfly/Upscope patterns documented: owner-adjudicated control handoff, per-tab roles, instant revoke, field masking) but a full multi-participant project; relay.ts integration stays parked. |
| Background/cloud execution (browser-closed checks) | Needs a Zo-side scheduler + FCM; #29's task specs are designed serializable so this is additive, not a rewrite (Distill's local-free/cloud-paid split is the model). |
| #20 tab compare, #21 page export, #11 web store listing | Lower competitive pressure; #11 becomes its own 0.2.x milestone (owner decision 2026-08-20: 0.2.0 = features only). |
| WebMCP (Chrome 149 origin trial) | Track it — an extension implementing site-declared tools would leapfrog first-party agent stacks — but the trial surface is too young to build on. |
