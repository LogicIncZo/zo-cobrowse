# 0.3.5 Security Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run security review round 2 on the post-0.3.0 surface (audit + in-round fixes) and ship `docs/qa/threat-model.md`, then release v0.3.5.0 through the standing train.

**Architecture:** Audit-first (the #243 pattern): re-run the mechanical inventories, deep-dive the three surfaces where 0.3.1–0.3.4 concentrated new risk (Jev egress, workspace write-back, recorder/compose privacy), extend the adversarial e2e only where the surface actually grew, and write every verdict into `security-review.md` round 2 + a new living threat-model doc. Findings disposition: nits fixed in-round (TDD), P1–P3 as `0.3.5.N` cycles.

**Tech Stack:** bun (unit/integration), Playwright + `e2e/mock-zo/server.mjs` (adversarial e2e), VitePress (docs), gh CLI (issues/PRs/releases).

**Spec:** `docs/superpowers/specs/2026-09-25-0.3.5-security-lane-design.md` — tickets [#383](https://github.com/LogicIncZo/zo-cobrowse/issues/383) (SEC1), [#384](https://github.com/LogicIncZo/zo-cobrowse/issues/384) (SEC2), milestone `0.3.5`.

## Global Constraints

- Baseline to diff against: `docs/qa/security-review.md` round 1 — **134 inventory sites, 0 external surfaces, 0 page-message listeners**, roster of 40 message types, content router = 3 types (`RECIPE_RECORD_STATE`/`CAPTURE_CONTEXT`/`EXECUTE_ACTION`).
- Branch flow: PR #382 (spec + this plan) merges to `dev` first; every task then branches `fix/<n>-<slug>` from `dev`, PR back to `dev`. Merge commits for promotions only.
- Pre-commit gate runs `bun run verify` — keep it on; bypass with `core.hooksPath=/dev/null` only on hook false positives (never on a red verify).
- **No prompt changes expected.** If any fix touches `lib/prompt.js`/`lib/modes.js` prompts or a Mode's knobs, run `bun run evals:live` in that fix's PR (ZO_API_KEY in `.env`).
- Findings queue `docs/qa/findings/` must be empty at release; ledger rows in `security-review.md` are the audit record (not findings-queue entries unless a red matrix/spec results).
- Sensitive keys stay out of `storage.sync` (`SENSITIVE_KEYS` routing); secrets never in URLs, bodies, or logs (`lib/debug-log.js` discipline).
- Version: 4-segment `0.3.5.0` in `extension/manifest.json` (`version` + `version_name`) and `package.json`; tag `v0.3.5.0`.
- VitePress build (`cd docs && bun install --frozen-lockfile && bun run docs:build`) BEFORE committing any docs change.
- Commit subjects: conventional, `(#<issue>)` suffix.
